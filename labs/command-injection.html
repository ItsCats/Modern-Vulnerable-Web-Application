Target: NetDiag network tools

web01 · www-data

NetDiag is an internal dashboard that lets support staff check whether a host is reachable. Behind the form, the server runs ping through the system shell. The shell here is simulated. It implements the parts of /bin/sh that matter for this attack: separators, pipes, quoting, variable expansion, command substitution and redirection.

Input is validated against a strict allowlist pattern, and the command runs as an argument vector with no shell. Even an unexpected value would reach ping as a single literal argument.

How the attack works

Root cause

Functions such as system(), exec() and subprocess.run(..., shell=True) pass a single string to a shell, which splits it into commands using metacharacters like ;, &, |, $( ), backticks and newlines. When user input is part of that string, the user decides which commands run.

Impact

  • Full remote code execution with the privileges of the web application.
  • Theft of source code, secrets and environment variables.
  • Lateral movement into internal networks, reverse shells and persistence.

Why the Medium fix fails

POSIX shells have many ways to start a command. Blocking ;, && and | still leaves &, newlines (sent as %0a in a raw request), $(command) and `command`, and ${IFS} can stand in for a space. Blocklists can't keep up with a full programming language.

Remediation

  • Prefer a library API to shelling out. Use a socket or ICMP library rather than calling ping.
  • If you must run a program, pass an argument array with shell=False (execFile in Node, ProcessBuilder in Java), and use -- to end option parsing.
  • Validate input against a strict allowlist pattern before using it.
  • Run the service with minimal privileges and in a sandbox (container, seccomp, no outbound network).
